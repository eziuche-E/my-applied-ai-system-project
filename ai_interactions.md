# AI Collaboration and Agent Tool Evidence

## Project 4 request and implementation record

The student asked to extend the original guessing game with a coach on the side, random try limits, a new random range each round, live probability explanations, retrieval, strategy planning, and reliability checks. They authorized implementation and useful supporting additions.

The implemented coach is a local symbolic agent with observable tool calls. It does not expose private chain-of-thought or use a hosted language model.

### Observable agent workflow

| Step | Action | Observable result |
|---|---|---|
| 1 | Route the question and check length/scope | Supported intent or safe refusal |
| 2 | `read_public_game` | Limits, tries remaining, observed hints, feasible interval; no secret |
| 3 | `retrieve` | IDs of the actual custom notes used to form the answer |
| 4 | `calculate_odds` | Exact candidate count, immediate odds, best-play odds, comparison policy |
| 5 | `plan_guess` | Midpoint and intervals for either next hint |
| 6 | `verify` | Public-context, probability, achievable-coverage, recommendation, and status checks |
| 7 | Render or fail closed | Detailed answer with source passages, or no invented advice |

### Committed intermediate tool logs

[assets/evaluation.json](assets/evaluation.json) contains complete question/answer records and intermediate tool-call results under `interactions[].trace`, including the public snapshot used for each answer. These records are generated by the actual coach, not reconstructed theoretical traces.

For `after-hints`, the tool log records:

```text
read_public_game: range 1–100; limit 5; 2 observations; 3 tries left; candidates 51–74
retrieve: strategy and probability references
calculate_odds: 24 candidates; next=1/24; best=7/24; blind=1/8
plan_guess: recommend 62; Too High → 51–61; Too Low → 63–74; 2 tries after the move
verify: passed
```

The exact current-run JSON is authoritative. Generate it again with:

```bash
python evaluate.py --output assets/evaluation.json
python demo.py --scenario all --json
```

The UI's **Sources & tool activity** expander shows the same events for a live game; its download retains up to 50 public interaction records. Runtime disk logs retain bounded metadata and exclude raw questions and hidden secrets.

### Development decisions and corrections

- Accepted direction: integrate the coach with the existing game and prevent hidden-secret access.
- Student-directed revision: replace the original fixed difficulty ranges/limits with randomized rounds and compute probability from the actual remaining tries.
- Supporting additions: what-if analysis, candidate tracking, no-cost invalid input, human-approved suggestions, snapshot checks for stale advice, session scorekeeping, and independent evaluation.
- Testing correction: a first secrecy assertion matched digits inside CSS. It was changed to compare active-game content across different secrets with identical public data.
- Browser automation correction: wait for Streamlit's asynchronous rerun before checking that a suggestion populated the input. Automated UI assertions also verify the action does not submit a guess.

Current evidence and limitations are documented in [model_card.md](model_card.md). No human study, fine-tuning run, or two-model comparison is claimed.
